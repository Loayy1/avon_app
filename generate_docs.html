1. الملخص التنفيذي والأهداف المحققة

تم تنفيذ تحول معماري جذري وشامل لتطبيق مستحضرات التجميل، حيث تم الانتقال من كود يعتمد على استدعاءات الشبكة المباشرة داخل واجهات المستخدم (Tight Coupling & Monolithic Views) إلى بنية معمارية نظيفة (Clean Architecture) مع فصل تام للمسؤوليات (Separation of Concerns).

🎯 أبرز المتطلبات التي تم إنجازها بنجاح:
  • إنشاء فرع منفصل على Git: إنشاء ودفع فرع feature/cart-api-integration لضمان أمان الفرع الرئيسي وسهولة المراجعة.
  • ربط Cart API من ملف Postman (avon.json): ربط المسارات /api/Cart (عرض)، /api/Cart/add (إضافة)، /api/Cart/update (تعديل كمية)، و /api/Cart/remove/{id} (حذف).
  • منع إعادة بناء الصفحة بالكامل (Fix Full Page Rebuild): عزل زر الإضافة في ويدجت مستقل _AddToCartButton واستخدام خاصية buildWhen في صفحة Home لمنع اختفاء المحتوى أو إعادة تحميل الشاشة.
  • حساب الفاتورة ديناميكياً (Dynamic Invoice): احتساب المجموع الفرعي ($Subtotal = \sum Price \times Quantity$) والشحن والضرائب والإجمالي الفعلي، وتمريره بسلاسة لشاشة إتمام الشراء (Checkout).
  • تطبيق Clean Architecture على كامل المشروع: إنشاء طبقات Data (Models + RemoteDataSources + RepoImpls)، و Domain (Abstract Repositories)، و Presentation (Cubits + States + Views) لكافة ميزات التطبيق.

2. المخطط الهيكلي للبنية المعمارية النظيفة (Clean Architecture Flow)

يعتمد تدفق البيانات في التطبيق على مبدأ التبعية الأحادية، حيث لا تعتمد طبقات العمل (Domain) على أي تفاصيل تقنية خارجية، بينما تتواصل واجهات المستخدم مع المتحكمات (Cubits) فقط.

Presentation Layer
Widgets & Screens
UI & Listeners
←
State Management
Cubits & States
Reactive Logic
←
Domain Layer
Repository Contracts
Pure Dart
←
Data Layer
DataSources & Models
Dio & Cache

تفصيل طبقات البنية المعمارية:

1. طبقة النواة المشتركة (Core Layer)

تحتوي على العناصر العامة التي تشترك فيها كافة أجزاء التطبيق دون الارتباط بميزة محددة:

  • ApiEndpoints: ثوابت مسارات وعناوين الخادم الموحدة.
  • DioHelper: عميل HTTP معدّ مسبقاً مع Bearer Token تلقائي.
  • CacheHelper: إدارة التخزين المحلي الآمن عبر SharedPreferences.
  • Failures: تصنيف أخطاء الشبكة والخادم والتفويض.

2. طبقات الميزات (Feature Layers)

كل ميزة (Auth, Home, Categories, Cart, Profile) تنقسم داخلياً إلى:

  • Data: تشمل Model لتحويل JSON، و RemoteDataSource لاستدعاء الـ API، و RepositoryImpl لتنفيذ العقود.
  • Domain: تشمل Repository المجرد كعقد رسمي.
  • Presentation: تشمل Cubit لإدارة العمليات وإطلاق الـ States للواجهات.

3. ميزة سلة المشتريات (Cart API) وحل مشكلة إعادة البناء

كانت سلة المشتريات تعتمد سابقاً على قيم وهمية (Mock Data) دون اتصال فعلي بالخادم. تم ربطها بالكامل مع الـ Endpoints المستخرجة من ملف الـ Postman (avon.json) وفقاً للمواصفات التالية:

العملية (Operation) طريقة الإرسال (Method) المسار (Endpoint) طريقة تمرير المعاملات (Parameters)
عرض السلة (Get Cart) GET /api/Cart Header: Authorization: Bearer <Token>
إضافة منتج (Add Item) POST /api/Cart/add Query Parameters: ?productId=1&quantity=1
تعديل الكمية (Update Item) PUT /api/Cart/update Query Parameters: ?productId=1&quantity=2
حذف منتج (Remove Item) DELETE /api/Cart/remove/{productId} Path Variable: {productId}

حل مشكلة وميض الصفحة وإعادة بنائها بالكامل (Page Rebuild Fix)

🔍 تشخيص المشكلة السابقة:

عند الضغط على زر "إضافة إلى السلة" من الصفحة الرئيسية، كان الـ HomeCubit يطلق حالة عامة HomeAddToCartLoadingState. وبما أن صفحة HomeView كانت تستمع للحالة بدون شرط تصفية (buildWhen)، كان استدعاء build() يُعاد بالكامل وتسقط الشاشة في الحالة الافتراضية Text("Please call the method") مما يسبب اختفاء المحتوى ووميضاً مزعجاً للمستخدم.

✅ الحل الهندسي المنفذ:
  1. عزل زر الإضافة في ويدجت مستقل: تم إنشاء _AddToCartButton داخل customs_widget.dart مع حالة تحميل محلية (_isLoading) لتحديث مؤشر الزر فقط دون التأثير على البطاقة أو الشاشة.
  2. استخدام شرط التصفية (buildWhen): تمت إضافة buildWhen: (prev, current) => current is HomeSuccessState || current is HomeLoadingState في HomeView لضمان عدم إعادة رسم الصفحة الرئيسية نهائياً عند عمليات السلة.

الحساب الديناميكي للفاتورة (Dynamic Invoice Calculation)

تم بناء الحسابات المالية داخل CartCubit بشكل فوري وتفاعلي، حيث يتم تحديث الفاتورة فورياً محلياً وبشكل متزامن مع الخادم: 

// معادلة حساب المجموع الفرعي ديناميكياً داخل CartCubit:
double get subtotal => items.fold(0.0, (sum, item) => sum + (item.price * item.quantity));
double get shippingFee => items.isEmpty ? 0.0 : 20.0;
double get tax => subtotal * 0.14; // 14% ضريبة القيمة المضافة
double get total => subtotal + shippingFee + tax;
⚡ التحديث التفاؤلي الفوري (Optimistic UI Updates):

عند قيام المستخدم بزيادة أو إنقاص كمية عنصر داخل السلة، يتم تعديل الكمية وإعادة حساب الفاتورة محلياً في نفس اللحظة (Zero Latency) مع إرسال الطلب إلى الـ API في الخلفية. وفي حال حدوث أي خطأ في الشبكة، يتم التراجع عن التعديل وإخطار المستخدم برسالة تنبيهية.

4. تفصيل الميزات المنفذة وفق معمارية Clean Architecture

🔐 1. ميزة المصادقة والحسابات (Authentication Feature)

المسار: lib/features/auth/ و lib/views/auth/

  • Data Layer: AuthRemoteDataSource للاتصال بمسارات /api/Account/Login و /Register و /verify-code و /reset-password. الموديل AuthResponseModel يستقبل كائن المستخدم والتوكن.
  • Domain Layer: AuthRepository يحدد العقود القياسية لعمليات الدخول والتسجيل والتحقق.
  • Presentation Layer: LogInCubit, RegisterCubit, VerifyCubit, ForgotPasswordCubit, CreatePasswordCubit. تم ربط التوكن وتخزينه تلقائياً في CacheHelper لتغذية الـ Headers في باقي الطلبات.

🏠 2. ميزة الصفحة الرئيسية والمنتجات (Home Feature)

المسار: lib/features/home/ و lib/views/pages/home/

  • Data Layer: HomeRemoteDataSource يستدعي مسارات جلب المنتجات /api/Products مع تحويلها عبر ProductModel (دعم الصور والأسعار والتقييمات).
  • Domain Layer: HomeRepository يقدم واجهة تجريدية للحصول على قائمة المنتجات.
  • Presentation Layer: HomeCubit يستقبل الـ Repository كـ Dependency Injection، ويدير حالات التحميل والنجاح والفشل، مع توفير زر الإضافة المعزول.

📁 3. ميزة التصنيفات والفلترة (Categories Feature)

المسار: lib/features/categories/ و lib/views/pages/categories/

  • Data Layer: CategoriesRemoteDataSource لجلب قائمة الأقسام من /api/Categories، بالإضافة لمنتجات قسم محدد. الموديل CategoryModel.
  • Domain Layer: CategoriesRepository كواجهة مجردة.
  • Presentation Layer: CategoriesCubit مع حالات CategoriesLoadingState, CategoriesSuccessState, CategoriesFailedState.

🛒 4. ميزة سلة المشتريات وإتمام الدفع (Cart & Checkout Feature)

المسار: lib/features/cart/ و lib/views/pages/cart/

  • Data Layer: CartRemoteDataSource يغطي كافة عمليات السلة مع دعم استجابات JSON المسطحة والمتداخلة (Flat & Nested JSON) داخل CartItemModel.
  • Domain Layer: CartRepository يمثل طبقة الأمان وعزل تفاصيل Dio.
  • Presentation Layer: CartCubit يدير العمليات وحساب الفاتورة بدقة، وتمرير المجموع الفعلي إلى شاشة CheckoutView مع زر تنفيذ الطلب.

👤 5. ميزة الملف الشخصي (Profile Feature)

المسار: lib/features/profile/ و lib/views/pages/profile/

  • Data Layer: ProfileRemoteDataSource لجلب وتحديث بيانات الملف الشخصي UserProfileModel من الخادم.
  • Domain Layer: ProfileRepository.
  • Presentation Layer: ProfileCubit لعرض بيانات المستخدم وتسجيل الخروج الآمن بمسح التوكن من الـ Cache ونقل المستخدم لصفحة الدخول.

6. حل مشكلة اتصال الإنترنت في حزم أندرويد (Android APK Network Fix)

🔍 تشخيص مشكلة تسجيل الحساب في نسخة الـ APK:

عند بناء التطبيق كـ APK وتشغيله خارج بيئة التطوير (Debug)، فشل التطبيق في إنشاء الحسابات والاتصال بالخادم. والسبب الهندسي الدقيق هو:

  • ملف android/app/src/main/AndroidManifest.xml لم يكن يحتوي على تصريح الإنترنت INTERNET (حيث كانت فلاتر تضعه فقط في مجلد debug المخصص للتطوير).
  • أنظمة أندرويد 9 فما فوق (API 28+) تحظر أي حركة شبكة غير مشفرة أو شهادات غير موثقة ما لم يتم تفعيل usesCleartextTraffic و networkSecurityConfig.
✅ التعديلات المنفذة على ملفات أندرويد:
  1. إضافة تصاريح الشبكة الكاملة في AndroidManifest.xml:
    <uses-permission android:name="android.permission.INTERNET"/>
    <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE"/>
    <uses-permission android:name="android.permission.ACCESS_WIFI_STATE"/>
  2. إنشاء ملف تكوين أمان الشبكة android/app/src/main/res/xml/network_security_config.xml لتمكين حركة الشبكة وشهادات النظام بأمان.
  3. ربط android:networkSecurityConfig="@xml/network_security_config" و android:usesCleartextTraffic="true" داخل وسم <application>.
  4. ترقية DioHelper لمعالجة استثناءات الشبكة وعرض رسائل الخطأ التفصيلية بدلاً من رسالة عامة.
